### Cms

Back-office screens for venues, media (photos, rooms, documents), landing pages and text blocks, plus the staff statistics screens. Read it by hand when `Portal` reuses a Cms class or when you add a venue write to the back office. Shell, UI kit, extension points, JSON conventions: `module-admin.md`; venue write side: `module-venues.md`.

## Boundaries and conventions

- **Write path (S8):** every venue, photo, room and document write is a `Venues\Command` on `command.bus`; Cms uses Venues and Media only via commands, exceptions, value objects and helpers, never entities, repositories or handlers, and owns only `content_blocks`. `Portal` reuses the card forms and saver, the photo upload and API classes, `TownOptions`, `VenueListQuery` and the photo and preview templates: changes there reach `/konto`.
- **Save contract:** an editor sends the token it was loaded with (card `loadedAt` = `updated_at` in Unix seconds; photo, room, document `token`; content `version`); stale is a 409 with input kept and a reload link. Unchanged cards, document titles and content editors dispatch nothing (no audit row, `cms_edited_at` or purge).
- **Roles, CSRF:** `ROLE_EDITOR`; only `admin_locations_delete` is `ROLE_ADMIN`. HTML token forms check the token in the controller and flash `flash.action_failed`: `#[IsCsrfTokenValid]` on HTML sends a logged-in editor to the login page.
- **Strings:** domain `cms`, one top-level prefix per feature, validators `cms.<feature>.*`. `CmsFlash::message()` keeps domain `cms` through the session (`_flash` uses `admin`). Staff screens say **Eintrag/Einträge** for a venue (names keep `locations`); `cms` keys shared with `/konto` keep "Location": `venue.error.too_many_photos`, `address.help.region`, `address.distances_help`, `preview.banner`, `preview.google_rating_hidden`, `photos.details.gallery_option`, `photos.remove.last`, `error.not_found`, `error.stale`, and `stats` `venue.visitors_note`.
- **Verlauf:** the 3 newest audit rows read `history.command.<Command>`. Every auditable `Venues\Command` needs that label in `cms` (listed in `CmsTranslationKeysTest`) and a case in `VenueCommandAuditTest`; without a label the row silently reads `history.command.fallback`. Keep the four retired labels `RateVenue`, `AddVenueReview`, `ChangeVenueReview`, `RemoveVenueReview` for old audit rows.

## Venue screens and editor

- **Routes** (`...` = `/admin/locations`): every name starts `admin_locations` (keeps the sidebar item active); `{number}` is `VenueNumber::REQUIREMENT` `[1-9]\d{0,8}`, never `\d+` (`venues.number` is an INTEGER; ten digits would be a 500). `admin_locations` `GET ...` (invalid filters give the unfiltered list at 422), `admin_locations_new` `GET|POST .../neu`, `admin_locations_edit` `GET .../{number}`, `admin_locations_publish|unpublish` `POST .../{number}/publizieren|unpublizieren` (back to the editor), `admin_locations_delete` `POST .../{number}/loeschen` (unpublished only; then the list, else back to the editor), `admin_locations_preview` `GET .../{number}/vorschau`, `admin_api_cms_towns` `GET /admin/api/cms/towns?q=` (Geo's `PlaceLookup`, no external call).
- **Read models:** `VenueListQuery::byNumbers()` and `quickSearch($q, $limit, ?$status)` (Portal's overview and searches). The "Unvollständig" tab counts `photo`, `inquiry_email`, `summary`, `main_building` (`dashboard.incomplete.missing.<code>`); the publish checklist `VenueEdit::missingForPublish()` is `summary`, `main_building`, `photo`, `inquiry_email` (D60; `editor.checklist.item.<code>`, also Portal's refusal wording).
- **Publish, preview:** `VenueStatusController::publish()` reads `PublishVenue`'s answer from the `HandledStamp` and, when true, calls `VenueEvents::newVenuePublished()` (`NewVenuePublished` has no subscriber since F12, but every new caller of `PublishVenue` must still do the same). The preview (`venue/preview.html.twig`) is the public detail page plus a banner and must reach no search engine or guest: `noindex`, no canonical, hreflang, JSON-LD or inquiry form, no Google call (notes replace its `inquiry` and `google_rating` blocks, so the back-office CSP holds); default locale only, 404 without it.
- **Cards** (`VenueCard`: `basics, texts, address, terms, event, contact, faq, google`): each has a form `venue_<card>`, a POST route `admin_locations_<card>` at `.../{number}/{stammdaten,texte,adresse,merkmale,veranstaltung,kontakt,faq,google-bewertung}` and one `Venues` command; a failed save (422, 409) re-renders only that card. The Veranstaltung card (F3, was "Hochzeit"; `VenueCard::Event`, anchor `veranstaltung`, `VenueEventType`/`VenueEventData`/`VenueLocaleEventType`/`VenueLocaleEventData`, `_card_event.html.twig`, strings `cms: event.*`, history label `ChangeVenueEventFacts`) owns the price level, seated and standing capacity, per locale `ambience`, `capacity_note` and `opening_hours`, and the chips of `suitable_for` (event types, checked against the plan), `catering`, `technology`, `amenity` and `language` (`VenueEventData::GROUPS`, pinned equal to `ChangeVenueEventFactsHandler::GROUPS`; F11 moved event types and technology here); the Merkmale card keeps setting, building, infrastructure, furniture and surroundings; party, curfew and the curfew's `TriState` are gone (the FAQ card still uses `TriState`). A data class implements `VenueCardData` (`from()` must be deterministic: it is built for the form and again for the diff `ChangedFields::between()`, canonical: trimmed, CRLF folded, `''` = null, lists sorted) and uses `CarriesLoadedAt`, which validates the hidden token itself, because hidden fields escape `AdminTextConstraintExtension`. `data-unsaved-guard` forms warn before the page is left.
- **Form rules:** a rule may refuse more than its DB CHECK, never less (`VenueContactRulesTest`). The ICU formatter throws on invalid UTF-8 in a message parameter (a 500 for a 422): `Regex`/`Email` take `normalizer: 'mb_scrub'` (not `trim`), a field `invalid_message_parameters: ['{{ value }}' => '']`. Coordinates and distances are strings (`DecimalTextType`; `NumberType` rounds), tri-state answers `TriState`. Form tests are Integration (`CleanText` reaches a form only under an `/admin` request); `VenueCardFormsTest::values()` sends a checkbox only when checked.
- **Address:** "Ortsmitte übernehmen" (`useTownCentre`, always dispatches) is a second submit behind a hidden default one, so Enter never overwrites coordinates. **Contact:** `InstagramProfileTransformer` turns a handle, `@handle` or URL into `https://www.instagram.com/<handle>` (else `cms.venue.instagram.invalid`); a stored value naming no profile stays as stored when sent back unchanged, so an untouched field never blocks the card.
- **Google card** (staff only): `placeId` (`GooglePlaceId::PATTERN`, `mb_scrub`) and `ratingHidden`, shown only with a loaded ID (`chk_venues_google_rating_hidden`). `renderEditor()` passes `google_check_url` (null without an ID) to every card include (they take a fixed variable list). Never stamps `cms_edited_at` (`close(markCmsEdited: false)`).

## Photos, rooms, documents

- **Pages** (`{id}` is `Requirement::UUID`, so the route walker fills it and `.../neu` never collides; a move is two routes, never `{direction}`): `admin_locations_photos` `.../{number}/fotos` and `admin_locations_rooms` `.../{number}/raeume` host the islands `photo-manager` and `room-editor` and need JavaScript. Documents are a server page: `admin_locations_documents` `GET|POST .../{number}/dokumente`, `_documents_edit` `.../dokumente/{id}`, `_documents_up|down` `.../{id}/nach-oben|nach-unten`, `_documents_remove` `.../{id}/loeschen` (token `cms_document`).
- **JSON API** (`/admin/api/cms/venues/{number}`, `admin_api` header token): `admin_api_cms_photos_{add,order,alt,room,remove}` = `POST /photos` (multipart `file`, optional `roomId`; 201 `{photo, duplicate: false, photos}`, the same file in the same scope 200 `duplicate: true`), `PUT /photos/order` `{roomId, ids}`, `PUT /photos/{id}/alt` `{loadedAt, alts}`, `PUT /photos/{id}/room` `{roomId}` (a missing key is 422, `null` is the gallery), `DELETE /photos/{id}`, all answering `{photos}`; `admin_api_cms_rooms_{add,order,change,remove}` = `POST /rooms` (201 `{room, rooms}`), `PUT /rooms/order` `{ids}`, `PUT /rooms/{id}` (+`loadedAt`), `DELETE /rooms/{id}`, all answering `{rooms}`. An order body must hold exactly the scope's ids (else 409). Every write returns the full list, which the island adopts, so tokens and positions never go stale.
- **Shapes** (`ManagedPhoto`/`ManagedRoom::toArray()`): photo `{id, roomId, position, thumbnailUrl, width, height, dominantColor, widths, formats, alts, token}`; room option `{id, name, position}`; room `{id, position, names, descriptions, capacityMin, capacityMax, areaM2, heightM, floorMaterial, seating, fromContent, photoCount, token}` (`heightM`, tokens: strings; `seating`: every `Seating` value to `{min, max}`).
- **Errors:** `{"errors": {field: [message]}}`; 404 and 409 use field `''`; 422 fields are dotted paths (`names.de`, `alts.de`, `file`) built by `VenueMediaApi`, not `ValidationErrors::fromForm()`. `failure()` maps `VenueNotFound`/`VenueRowNotFound` to 404, `StaleEdit` 409, `UnreadableImage` 422 on `file`, `VenueRuleViolation` 422 on its field, and rethrows the rest. The room body (`RoomType`) takes no unknown key (422) and a key left out is cleared: send the drawer's whole state. A JSON body above `MAX_BODY_BYTES` (1,000,000) counts as empty.
- **Upload limits**, only in `VenuePhotoUpload`, in front of gd, from the file header: photo <= 10 MB as JPEG, PNG or WebP; `AddVenuePhoto::MAX_PHOTOS` (30) per scope; PDF <= 15 MB. One pixel cap for all types, `MEDIA_MAX_PIXELS` (20,000,000; large files are refused, not handled); `MEDIA_MAX_PORTRAIT_RATIO` (2) limits height / width, even a small 300x900; landscapes none (`PhotoUploadLimits`, EXIF-aware). Refusals are 422s naming the limit; a JPEG with over 100 scan markers (`FF DA`) is `cms.photo.unreadable`. No memory guard, no 503: php-fpm keeps freed memory, so the caps must hold over a run of uploads at `memory_limit` 256M; raise a limit only with `memory_limit`; never put one in `PhotoPipeline` or `ImageVariantGenerator` (imported photos above 40 MP would fail); never call `raiseBatchMemoryLimit()` in a request.
- **Transport:** PHP `upload_max_filesize` 25M, `post_max_size` 26M, `max_execution_time` 60 (dev; production 120 in `public/.user.ini`); nginx `client_max_body_size` 26m equals `post_max_size`, so an oversize body is nginx's HTML 413, while PHP's own case (body dropped) answers `too_large`. `file-limit.js` stops a too-big PDF before sending. The ICU formatter chokes on an invalid-UTF-8 client file name (a 500; `File`/`Image` always pass it): pass every upload through `Form\SafeClientName::of()`.

## Vue islands

Mounted by `admin_island()` from `venue/{_photo_manager,rooms}.html.twig`, which pass `endpoints`, `idPlaceholder` (`VenueMediaApi::ID_PLACEHOLDER`, replaced per row), `reloadUrl`, `labels` (`%name` tokens filled by `cms/text.js fill()`). No events; feedback is `useToast` and a `role="alert"` message from `failureOf()` (lost session or 403: reload link, 409 stale, 404 gone). `createWrites(key, apply)` (`run`, `send`) puts uploads and JSON writes on one line (a write beside an upload waits for the session lock, then fails the set check); ids and row tokens are read when the request leaves (`freshToken()`), form values at the press, a failure applies null (restores the old order). `createQueue({upload, maxBytes, onChange, hideDoneAfterMs})` (`add`, `retry`, `dismiss`, `running`) sends one file at a time and a lost session or 403 halts it for good. Also `upload.js` (the one XHR), `charCount` (trimmed code points, as the server's `Length`), `CmsField.vue` (form-theme markup) and `UiSortableList`'s scoped slot `item` (`{item, index}`).

- **`PhotoManagerIsland`** props: photos, rooms, locales, defaultLocale, venueName, maxBytes, accept, altMax, idPlaceholder, endpoints (`upload`, `order`, `alt`, `room`, `remove`; without `room` no room select), reloadUrl, labels. Alt and room are two requests, only for what changed, alt first (it carries the row token a room move bumps). A reorder sends exactly the scope's ids (`orderedIds()`; else 409). `beforeunload` warns for unsaved alt text and a running queue.
- **`RoomEditorIsland`** props: rooms, locales, defaultLocale, floorMaterials, seatingTypes, nameMax, descriptionMax, idPlaceholder, endpoints (`add`, `order`, `change`, `remove`), reloadUrl, labels. The drawer posts exactly `RoomType`'s keys (PUT adds `loadedAt`), aborts after `SAVE_TIMEOUT_MS` (90 s); a field error is the API's dotted path, any other lands in the drawer's alert, so none is dropped. `UiDrawer`/`UiModal` take `busy` (`inert`, `aria-busy`, no close): the drawer stays open until its save answers, so an answer meets only its own room.
- **Room range (F4):** while a layout has a max, `RoomEditorIsland` locks `capacityMin`/`capacityMax`, fills them from the layouts (mirror of `Seating::guestRange()`) and shows `rooms.help.capacity_from_layouts`; `RoomData` skips its room min/max rule then.
- **A11y:** photo tiles are `<button aria-pressed>` with a visually hidden position label; reordering via `UiSortableList` move buttons and `moved` live text; picking a photo focuses the panel heading; queue state is `aria-live="polite"`, a queue button that removes itself returns focus to the queue; Save is `aria-disabled`, not `disabled`.

## Landing pages and text blocks

- **Table `content_blocks`:** PK `pk_content_blocks (key, locale)` (natural key), `body_markdown` (`chk_content_blocks_body`: not blank, so a block without text has no row and clearing a field deletes it), `updated_at`, `chk_content_blocks_{key,locale}`. Keys: a module block (`listing.intro`, `footer.note`) or `landing.<canton|town|building|event>.<code|town id>[.<canton> for an event page in a canton].<intro|title|description>`, by identity, never by slug. **A migration that renames a building code must `UPDATE content_blocks SET key = ...` for its `landing.building.<code>.*` rows**, or the texts are orphaned silently; a deploy that ran such SQL needs `cache:pool:clear cache.content_blocks` (`module-shared.md`), or the old snapshot serves for about two days.
- **Routes:** `admin_landing_pages` `GET /admin/landingpages` (pages with a published venue), `admin_landing_pages_edit` `GET|POST /admin/landingpages/{landing}` (`LandingKey::REQUIREMENT`; not a candidate: 404), `admin_text_blocks` `GET /admin/textbausteine` (every `ContentBlockDefinition`: declare one in Shared and it appears), `admin_text_blocks_edit` `GET|POST /admin/textbausteine/{key}` (`TextBlockKey::REQUIREMENT`; an undeclared key, a landing key included: 404).
- **Editors:** forms `landing_texts` and `text_block` (`data-counter-max` 600/60/155 from `LandingKey`, the definition's `maxLength()`; the page's computed default is the placeholder, via `VerbatimText`), each with a hidden `[version]` validated by its own `NotBlank` + hex `Regex`. The landing aside previews the search result (`serp-preview.js`); a page under `landing.min_venues` has no URL and no "Seite ansehen".
- **Commands** (auditable; summary `{"locales", "fields"}`, names only, never text): `SaveLandingTexts`, `SaveTextBlock`. Both write through `ContentBlockWriter::apply()`, the one write path: inside the bus transaction only (else `\LogicException`); null or blank removes the row, a key left out stays, bodies stored trimmed; limits count code points of the trimmed text, as `char-counter.js` (`LengthCountTest`).
- **Stale rule:** `ContentVersion::of()` hashes every row of the editor's keys, all locales (`updated_at` in Unix seconds, body hash). The editor reads `ContentBlockStatusQuery::versionOf()` before `bodies()`; the writer takes `pg_advisory_xact_lock(hashtextextended('content_blocks:' || subject, 0))`, recomputes from the entities and throws `StaleContentBlocks` on a mismatch, so another editor's insert, delete or same-second revision is a 409, never overwritten.
- **After the commit,** when a row changed: `RefreshContentBlockSnapshot` (rebuilds, never deletes: peeking pages keep the footer note), then `PurgeListingsCache`, both `DispatchAfterCurrentBusStamp`, in that order (`SaveContentBlocksTest` pins it). A failed refresh is logged, never with the exception message; the save stands, the purge runs, the snapshot's age heals it (`module-shared.md`).
- **Editor hint:** a block whose page shows paragraphs of its own implements `Shared\Extension\ContentBlockPageDefault` (its `fallback()` stays null); hint order: declared fallback, page default, `no_fallback`. Only `HomeTextBlock` does (guarded by `TextBlockEditorTest`).

Server page, no JS: the list (`ReadModel\VenueVideosQuery`, `ManagedVideo`) marks rows above the plan's `videos_max` «Nicht sichtbar (Plan)», links each video at its provider and never embeds a player; the card (`Form\VideoUrlType`/`VideoUrlData`, a text field, 500 chars) takes a link; the handler's refusal is a 422 on the field. Partial `templates/admin/cms/venue/_videos.html.twig`.

**D60 (`inquiry-address-required`).** The checklist «Bereit zum Publizieren» has «Anfrage-E-Mail»; a refused publish reads «Noch nicht publizierbar. Es fehlt: …, Anfrage-E-Mail.» (`PublishGapLabels`, a noun like the other checklist gaps). Emptying «Anfrage-E-Mail» on the contact card of an online venue is a 422 with «Eine Location, die online ist, braucht eine Anfrage-E-Mail.» on the field (`VenueRuleViolation::inquiryEmailRequired()` via `VenueCardSaver`); take the venue offline first to remove it.
