### Cms

Back-office screens for venues, photos, landing pages and text blocks.

**Built in #24 (`cms-venues`).** No migration of its own (the schema is in `### Venues`), no new package. Design: `docs/reference/admin/{Locations,LocationEdit,Main}.dc.html`. Strings in `cms`; flashes are `Cms\ValueObject\CmsFlash` (a `TranslatableMessage`, which keeps its domain through the session).

- **Routes** (all `#[IsGranted('ROLE_EDITOR')]`; every name starts `admin_locations`, which keeps the sidebar item active, and #25's must too; `{number}` uses `Cms\ValueObject\VenueNumber::REQUIREMENT` `[1-9]\d{0,8}`, never `\d+`): `admin_locations` `GET /admin/locations` (`VenueListController`: status tabs `status` published|unpublished|incomplete, `q`, `tier`, `canton` (code or `none`), `address=missing`, `sort` name|tier|capacity|updated, `dir`, `page`, 50 per page; invalid filters give the unfiltered list at 422 with a notice above the table), `admin_locations_new` `GET|POST /admin/locations/neu` (`VenueCreateController`: name, tier, capacity → `CreateVenue` → the editor), `admin_locations_edit` `GET /admin/locations/{number}` and one POST per card, `admin_locations_<card>` at `…/{stammdaten,texte,adresse,merkmale,hochzeit,kontakt,faq,google-bewertung}` (`VenueEditController`; #53 replaced `bewertung` with `google-bewertung`, route `admin_locations_google`), `admin_locations_publish|unpublish` `POST …/publizieren|unpublizieren` and `admin_locations_delete` `POST …/loeschen` (`ROLE_ADMIN`, unpublished only; `VenueStatusController`, always back to the editor), `admin_locations_preview` `GET …/vorschau` (`VenuePreviewController`: the public detail template with a banner, `assets/styles/venues/_preview-banner.scss`, published or not, default locale, `noindex`, no canonical, hreflang, JSON-LD or inquiry form; 404 without a default-locale row), `admin_api_cms_towns` `GET /admin/api/cms/towns?q=` (`TownLookupController`: `ComboboxType` options from Geo's `PlaceLookup`, value "8706 Meilen"; no external call).
- **Editor cards** (`Cms\ValueObject\VenueCard`, in page order `basics, texts, address, terms, wedding, contact, faq, google` (#53: `rating` is gone); `route()`, `anchor()`, `formName()` `venue_<card>`, `formType()`, `dataClass()`): one form and one `Venues` command each. `Form\VenueEditorForms::form()|views()` builds them from `ReadModel\VenueEditQuery::find()`. A save is a 302 to `…/{number}#<anchor>`; `StaleEdit` is a 409 with the input kept and a reload link; invalid input or a `VenueRuleViolation` is a 422 on that card, the others fresh. Coordinates and distances are strings on `Form\DecimalTextType`, so they round-trip exactly; tri-state answers use `ValueObject\TriState` (`yes|no|unknown`). Address card: "PLZ / Ort" as a free-text combobox, canton select, street, coordinates, distances, regions (only while there is no town or canton); "Ortsmitte übernehmen" is a second submit (`useTownCentre`) behind a visually hidden default submit, so Enter saves; a hint names the town while `coordinates_from_town`. **Built in #26 (`cms-pages`).** Migration `Version20261031070024`; mapping `orm.mappings.Cms` (the module's first entity); no new package. The read side and the contracts are in `### Shared`. - **Table `content_blocks`** (entity `Cms\Entity\ContentBlock`, `revise()` false when unchanged; `ContentBlockRepository::byKeys()`, `add()`, `remove()`): PK `pk_content_blocks (key, locale)`, a natural key like `cantons` (documented exception to `EntityId`); `body_markdown` (`chk_content_blocks_body`: not blank, so a block without text has no row and clearing a field deletes it); `updated_at`; `chk_content_blocks_key`, `chk_content_blocks_locale`. Keys: a module block (`listing.intro`, `footer.note`) or `landing.<canton|town|building>.<code|towns.id>.<intro|title|description>`, by identity, never by slug. **A migration that renames a building code must `UPDATE content_blocks SET key = …` for its `landing.building.<code>.*` rows**, or the page's texts are orphaned silently, and a deploy that ran such SQL needs `cache:pool:clear cache.content_blocks` (see `### Shared`), or the old snapshot serves for up to about two days.
- **Routes** (class-level `#[IsGranted('ROLE_EDITOR')]`, unlocalized): `admin_landing_pages` `GET /admin/landingpages` (`LandingPageListController`: `typ` canton|town|building, `q` (name contains), `page`, `PER_PAGE` 50; every page with ≥ 1 published venue, its count, threshold state and last change), `admin_landing_pages_edit` `GET|POST /admin/landingpages/{landing}` (`LandingPageEditController`, `Cms\ValueObject\LandingKey::REQUIREMENT`; not a candidate is 404), `admin_text_blocks` `GET /admin/textbausteine` (`TextBlockListController`: every `ContentBlockDefinition`), `admin_text_blocks_edit` `GET|POST /admin/textbausteine/{key}` (`TextBlockEditController`, `TextBlockKey::REQUIREMENT`; an undeclared key, a landing key included, is 404). `ChecksAdminRoutes::routeSample()` fills them by requirement (`canton.zh`, `listing.intro`).
- **Editors:** forms `landing_texts[locales][<code>][intro|title|description]` (`#landing-texts-form`; intro `MarkdownType`; `data-counter-max` from `LandingKey::{INTRO,TITLE,DESCRIPTION}_MAX_LENGTH` 600/60/155; #17's text as placeholder through `ValueObject\VerbatimText`) and `text_block[locales][<code>][body]` (`#text-block-form`, `MarkdownType`, the definition's `maxLength()`), both with a hidden `[version]`, one `_locale_tabs` panel per enabled locale. The landing editor's `aside` is the search-result preview (`_serp_preview.html.twig`; `assets/js/admin/serp-preview.js` copies `data-serp-source` fields to `data-serp-target`, matched by `data-serp-locale`); a page under the threshold has no URL and no "Seite ansehen". `Form\ContentChanges::between()` diffs each locale over #24's `ChangedFields`; an empty diff flashes `landing.flash.unchanged`/`blocks.flash.unchanged` and dispatches nothing (no audit row, no purge). A save is a 303 back to the editor; `StaleContentBlocks` is a 409 with the input kept and a reload link (`text.error.stale`); `ContentTooLong` a 422 on its field. Templates `templates/admin/cms/pages/{landing_list,landing_edit,block_list,block_edit,_serp_preview}.html.twig`, styles `assets/styles/cms/_pages.scss`.
- **Commands** (auditable; summary `{"locales", "fields"}`, names only, never text): `SaveLandingTexts(keyPrefix, texts, version, changedFields, locales)` (texts locale → field → ?string; `AuditSubject('landing_page', prefix)`; `UnknownLandingPage` when `LandingPageSource::page()` is null) and `SaveTextBlock(key, bodies, version, locales)` (`AuditSubject('content_block', key)`; `UnknownContentBlock`). Both write through `Cms\ContentBlockWriter::apply(subject, keys, bodies, version): bool`, the one write path: inside the bus transaction only (`\LogicException` otherwise), null or blank removes the row, a key left out stays, bodies stored trimmed; limits by `ContentTooLong::check()` in code points of the trimmed text, as `char-counter.js` counts.
- **Stale rule (P8):** `ValueObject\ContentVersion::of($rows)` is SHA-256 over the sorted lines `key|locale|updated_at as Unix seconds|sha256(body)` of every key the editor covers, all locales (no rows: `sha256('')`); the editor reads it with `ReadModel\ContentBlockStatusQuery::versionOf()` before `bodies()` (`ContentBlockBodies`, `of($locale, $key)`; the lists use `byPrefix()`, `ContentBlockChanges`, `of($subject)`). The writer takes `pg_advisory_xact_lock(hashtextextended('content_blocks:' || subject, 0))`, recomputes from the entities and throws `StaleContentBlocks::forSubject()` on a mismatch, so another editor's insert, delete or same-second revision is a 409, never overwritten.
- **After the commit (P4):** when a row changed, `RefreshContentBlockSnapshot` (rebuilds the snapshot, never deletes it, so a page that only peeks keeps the footer note), then `PurgeListingsCache`, both with `DispatchAfterCurrentBusStamp`, in that order, so a page rendered after the purge reads the new text. A refresh that fails is logged by `RefreshContentBlockSnapshotHandler` (`Content blocks: the snapshot refresh failed ({exception_class} at {file}:{line}).`, never the exception's message), the save stands and the purge runs; saving the same text again changes nothing, so the snapshot's age heals it within about two days (see `### Shared`). Only a connection lost before the bus's own COMMIT of that message can still answer 500, and the redirect's GET needs the same database.
- **Extension points:** `LandingPagesNavigationItem` (`landing.nav`, icon `file-text`, priority 200) and `TextBlocksNavigationItem` (`blocks.nav`, `type`, 100), CMS section, below `LocationsNavigationItem` (300); the registry's prefix rule keeps them active on `…_edit`. `ShellTest` and `ExtensionPointsTest` pin the sidebar labels.

- **JSON API** (base `/admin/api/cms/venues/{number}`, #22's CSRF header): `admin_api_cms_photos_add` `POST /photos` multipart (`file`, optional `roomId`; 201 `{photo, duplicate: false, photos}`, the same file 200 `duplicate: true`), `_photos_order` `PUT /photos/order` (`{roomId, ids}`), `_photos_alt` `PUT /photos/{id}/alt` (`{loadedAt, alts}`), `_photos_room` `PUT /photos/{id}/room` (`{roomId}`), `_photos_remove` `DELETE /photos/{id}`, all answering `{photos}`; `admin_api_cms_rooms_add` `POST /rooms` (201 `{room, rooms}`), `_rooms_order` `PUT /rooms/order` (`{ids}`), `_rooms_change` `PUT /rooms/{id}` (+`loadedAt`), `_rooms_remove` `DELETE /rooms/{id}`, all answering `{rooms}`. Every write returns the full list, and the island replaces its state from it, so tokens and positions never go stale (PF10).
- **Answer shapes:** photo `{id, roomId, position, thumbnailUrl, width, height, dominantColor, widths, formats, alts, token}`, room option `{id, name, position}`, room `{id, position, names, descriptions, capacityMin, capacityMax, areaM2, heightM, floorMaterial, seating, fromContent, photoCount, token}` (`heightM` a string, `seating` keyed by `Seating` value to `{min, max}`, tokens strings). Errors are `{"errors": {field: [message]}}`; 404 and 409 use the field `''`; 422 fields are dotted paths (`names.de`, `seating.banquet.max`, `alts.de`, `file`, `roomId`, `ids`) from `Cms\VenueMediaApi`, not `ValidationErrors::fromForm()`, whose leaf names collide. `VenueMediaApi::failure()` maps `HandlerFailedException` (`VenueNotFound` and `VenueRowNotFound` 404, `StaleEdit` 409, `UnreadableImage` 422 on `file`, `VenueRuleViolation` 422 on its field) and rethrows the rest. The room body takes no unknown key (422); a key left out is cleared, so send the drawer's whole state. A JSON body above `VenueMediaApi::MAX_BODY_BYTES` (1,000,000) is refused as empty before it is decoded, and `PUT …/photos/{id}/room` without a `roomId` key is a 422 (`null` is the gallery).
- **Upload limits:** photos ≤ 10 MB (`VenuePhotoUpload::MAX_BYTES` 10,000,000, the island's client check uses the same figure), JPEG, PNG, WebP; PDFs ≤ 15 MB. Stack: `upload_max_filesize` 25M, `post_max_size` 26M, `max_execution_time` 60, nginx `client_max_body_size 26m`. nginx's limit equals PHP's, so an oversize body locally is nginx's HTML 413, which `adminFetch` and the XHR helper report as `RequestFailed(413)`; PHP's own branch (no files, no POST, `CONTENT_LENGTH` set) answers `too_large`. Set these limits for production in #20.
- **Pixel limits:** one cap for every type, `MEDIA_MAX_PIXELS` (`.env`, 20,000,000; `app.media_max_pixels`). Staff upload photos for the web, and the site shows at most 1920 px, so large files are refused, not handled. `MEDIA_MAX_PORTRAIT_RATIO` (2; `app.media_max_portrait_ratio`) limits height ÷ width; landscapes have no limit, and a small 300×900 image is refused too. The limits are read **only** by `VenuePhotoUpload`, in front of gd and from the file's header (`Cms\ValueObject\PhotoUploadLimits::isTooTall()` for the shape, compared without a division because `Assert\Image`'s `minRatio` rounds to two decimals, and reading both the stored shape and the shape after EXIF turns it, `ImageVariantGenerator::swapsAxes()`). Each refusal is a 422 naming its limit (`cms.photo.too_large`, `cms.photo.too_many_pixels`, `cms.photo.too_tall`). A JPEG with more than 100 scan markers (`FF DA`, counted in the raw bytes) answers `cms.photo.unreadable`: libjpeg's cost is per scan, so a small file could pin a worker (#44, F-M1). A php-fpm worker keeps freed memory for its next requests, so a cap must hold for a run of uploads: measured through the real route at 256M, 8 files at the limits of one type (20 MP at the worst width, PNG 18.9 MP, each 10 MB), then one of any type, in every order at 2 and 1 workers: 324 uploads, all 201, peak 81.8 % (209.6 MiB, PNG after PNGs). There is no memory guard and no 503: at 40 MP, 8 files then a PNG was a fatal, and lowering the caps was the fix. Raise a limit only together with `memory_limit`. Never put a limit in `PhotoPipeline` or `ImageVariantGenerator`, and never reuse #32's `BATCH_MAX_PIXELS` or `raiseBatchMemoryLimit()` in a request. `PhotoPipeline::stage()` renders first and stores the original afterwards, so a decode failure or fatal leaves none. `UiModal` and `UiDrawer` take `busy` (`inert`, `aria-busy`, no close): the room drawer stays open until its save answers, so an answer can only meet its own room.
- **Client file names:** the ICU formatter throws on invalid UTF-8 in any violation parameter, and `File`/`Image` always pass the client name, so a crafted name turns a 422 into a 500. Validate `Form\SafeClientName::of($file)` on every upload.
