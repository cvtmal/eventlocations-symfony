## New public route or cache header

1. Declare it localized (`i18n.md`). Cache only through `Shared\Http\PublicCache`: `page()` (`s-maxage`, `stale-while-revalidate`, `stale-if-error` a day), `listing($now)` (`s-maxage` to the next Zurich midnight: the order uses the day's seed, so pages 1 and 2 must share a day), `MISSING_TTL` 3600 (a thrown 404/410 via `#[Cache]`, which takes constants only and never overwrites a directive the controller set). Never a browser `max-age` on HTML, so a purge reaches a visitor on the next navigation (JSON only: `_search_count` `COUNT_BROWSER_TTL` 60, `_search_places` `PLACES_BROWSER_TTL` 3600). `health` is `no-store, private`. S10 still words `s-maxage=600`: the constants win.
2. No session, no cookie: only `/admin` and `/konto` start a session; only `COOKIE_ROUTES` (`merkliste`, `merkliste_toggle`, `merkliste_sync`) send a cookie, and they are `private, no-store`.
3. `PublicPagesStartNoSessionTest` walks every route outside `/admin` and `/konto` with every method and real parameters: add the route's `$parameters` entry, a `/_` route to `INTERNAL_ROUTES` (or `DEV_ONLY`), a route that is not `public` with an `s-maxage` to `PRIVATE_ROUTES` (e.g. `_stats_collect` `POST /_stats`: internal and private, 204, no session, no database connection). `Session::isStarted()` proves nothing after the response (the listener saves and closes it): check `getUsageIndex()`.
4. `PublicCacheHeadersTest` pins the exact `Cache-Control` and `Vary` per route and answer: add a row (`Tests\Support\Http\PublicRouteFixtures`).
5. A write that changes public pages purges after its commit: dispatch `Venues\Command\PurgeVenueCache` or `PurgeListingsCache` with `DispatchAfterCurrentBusStamp` (both invalidate the whole store: `HttpCacheClearer::invalidate()`).

## Cron jobs and Sentry monitors

**Cron jobs:** `deploy/crontab.txt` is the `deploy` user's crontab with exactly three lines on `current/bin/…` and a `MAILTO`; the server clock is Europe/Zurich. The scripts `cd -P`, so a run stays in one release across a switch:
- `bin/cron-midnight` (`5 0 * * *`) runs `app:http-cache:clear`; `bin/cron-cache-guard` (`2-59/5 * * * *`) runs it with `--if-over-limit`. They share `var/lock/cache-clear.lock` (`bin/cron-lock.sh`; in `shared/`, so it holds across releases): the midnight clear waits up to 60 s, the guard skips a tick, a lock older than 10 minutes is taken over.
- `bin/cron-daily` (`15 3 * * *`, one Neon wake-up) runs these steps in order, each even if an earlier one failed (a failure prints `cron-daily: <label> failed` and exits non-zero): `inquiries-purge` (`app:inquiries:purge`), `crm-refresh-stages` (`app:crm:refresh-stages`), `crm-renewal-tasks` (`app:crm:renewal-tasks`), `crm-backfill` (`app:crm:backfill-inquiries`), `inquiries-stuck` (`app:inquiries:report-stuck`), `stats-ingest` (`app:stats:ingest`), `pool-prune` (`cache:pool:prune`), `staging-sweep` (`var/import-staging` older than a day), `sessions-sweep` (`var/sessions` files older than 43200 minutes = `Admin\EventListener\IdleTimeoutListener::IDLE_SECONDS`, never shorter), `lock-sweep` (`var/lock/sf.*.lock` older than 180 minutes: a limiter window above that needs a longer age). The sweeps name `var/<dir>/` with a trailing slash: those directories are symlinks into `shared/`, and `find` does not follow a symlinked start.
- A good night prints nothing (cron mails any output): `bin/cron-midnight` shows the clear's output only on failure, the guard prints only when it clears, `bin/cron-daily` runs its commands `--quiet` except `crm-backfill` and `inquiries-stuck`, which print on purpose.

**Sentry monitors today** (append a note per new monitor):
- Backup: `.github/workflows/backup.yaml` pings the cron monitor `SENTRY_CRON_URL` (optional repository secret) with `?status=in_progress`, then `ok` or `error`; the monitor also catches a run that never happened. Manual `workflow_dispatch` until the owner adds the schedule once production holds data (`docs/operations.md`).
- Uptime: a Sentry uptime monitor on `/robots.txt` every 5 minutes, never `/health` (it queries the database and would keep Neon awake).
- The three `bin/cron-*` jobs have no monitor in the repo: their cron mail is the signal. The runbook gives the owner a crontab line that pings a `cron-daily` monitor after a good run (its URL is a secret, so it never enters `deploy/crontab.txt`).

## HTTP cache

- `when@prod` `framework.http_cache` only; dev and test stay uncached, so a test wires it by hand (`Tests\Support\Http\ThroughHttpCache`). The store, `var/share/<env>/http_cache` (`APP_SHARE_DIR=var/share`), survives `cache:clear`; only `app:http-cache:clear` empties it. **Only the web user may write it:** an unwritable `var/share/<env>` is a 500 on every URL (`/health` too); an unwritable store answers a new URL `miss/store-failed` and **any URL with a stale entry a 500**.
- `HttpCacheClearer` never throws (it logs class, file and line, never the message): `invalidate()` is the purge (metadata only, frees no disk); only `clear()` frees disk, and a request that looked up a body just before it answers Symfony's raw 500.
- `app:http-cache:clear [--if-over-limit]` calls `clear()` with no bus (`command.bus` would wake Neon) and exits 1 on failure. It runs at 00:05, in every deploy, after `app:geo:import-towns` and `app:media:regenerate` (they change pages without a purge), and with `--if-over-limit` every 5 minutes; a render that races a purge can store the old page, which stays until the next `clear()`, and a clear drops the `stale-if-error` fallback. **The size guard is the only bound on the store** (`Store` never evicts; every filter state, `?q=` and unknown slug is a new key): above `HTTP_CACHE_MAX_BYTES` (5 GiB) or `HTTP_CACHE_MAX_FILES` (1,000,000, the bound for small entries), both in `.env`, it clears, else it prints nothing. It overshoots by about one interval of write rate, so production's quota must leave room; a limiter that cannot save its count fails open on a full disk.
- A cached detail page shares one fill-time token, so the bot check (`Inquiries\Form\FillTimeToken`) only means "at least 3 s since that page was rendered".
- nginx (`docker/nginx/`; a change needs `docker compose restart nginx`): `/assets/` `public, max-age=31536000, immutable`; `/media/` `public, max-age=86400`, never `immutable` (`app:media:regenerate` rewrites the same URLs).
- **`getClientIp()` is the visitor's address behind HttpCache** (it rewrites `REMOTE_ADDR` and forwards the visitor), so limiters stay per visitor and `isSecure()` holds with no `trusted_proxies` value (`ClientIpBehindHttpCacheTest`).

## Security headers and CSP

- `SecurityHeadersListener` (priority -10, see its docblock) sets on every main response, `/admin` included: `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` (never `no-referrer`: the no-JS Merkliste toggle and the inquiry CSRF fallback read the same-origin `Referer`), `Permissions-Policy`, HSTS only when `isSecure()`, the CSP on `text/html`. Public pages are cached, so `script-src 'self'` has no nonce and inline code needs a hash; `/admin` is `no-store` and takes real nonces (`CspNonce`, `csp_nonce()`).
- Route-scoped policies live in `ContentSecurityPolicy`, chosen by the request attribute `_csp`: `google_maps` is the default of `nearby` only and alone grants `geolocation=(self)` (everything else keeps `()`); `google_places` is set per response by `Venues\Twig\VenueGoogleRatingExtension` when it renders Google's element. Neither takes a nonce or hash (their `style-src 'unsafe-inline'` works only while none enters it), so a hash added to the site policy must not reach them (`SecurityHeadersTest`). `GOOGLE_MAPS_JS_KEY` and `GOOGLE_MAPS_MAP_ID` sit in cached HTML, so a change needs `sh bin/prod-import purge`; `app:prod:check-env` refuses an empty or `DEMO_MAP_ID` Map ID once a key is set.
- All three policies carry `manifest-src 'self'` (F6); without it `default-src 'none'` blocks the manifest link.
- Real header bytes show only with `createClient(['debug' => false])`. `tests/bootstrap.php` wipes `var/cache/test` at every PHPUnit start, since a debug-off kernel never checks freshness.

## Content blocks

Cms owns the table `content_blocks`; Shared holds the contracts and the read side (SQL, no PHP dependency), so a public module declares and renders a block without naming Cms.
- Contracts (`Shared\Extension`): `ContentBlockDefinition` (tag `content_block.definition`; `key()` dotted lower-case, never `landing.*`; `maxLength()` counts code points of the trimmed text) collected by `ContentBlockRegistry` (a duplicate key throws `\LogicException`); optional `ContentBlockPageDefault` (editor hint: `### Cms`); `FooterNoteBlock` (`footer.note`, 300); `LandingPageSource` (Seo implements it) with `LandingPageEntry` (`blockKey($field)` gives `landing.canton.zh.title`).
- Reader `Shared\ReadModel\ContentBlocks`: one item `snapshot` in pool `cache.content_blocks`, no expiry. `text()` and `html()` fill a cold pool; `peek()` and `peekHtml()` never query; `refresh()` rebuilds after a Cms commit; a cache error never fails a page; every pool write holds the advisory lock `ContentBlocks::LOCK`, taken before the SELECT (`refresh()` waits, a cold read tries it and stores nothing if taken), so an older snapshot cannot replace a newer one; `text()` rebuilds a snapshot older than `MAX_AGE_SECONDS` (a day) while `peek()` keeps serving it, and any other item shape is a miss. That age cap heals a failed refresh, a restore or a direct SQL change in about two days (`text()` runs only on a PHP render and listings stay cached until Zurich midnight). After a direct SQL change run `make sf c="cache:pool:clear cache.content_blocks"` and `make sf c="app:http-cache:clear"`, then hit the plain listing (`cache:clear` leaves the pool alone). `MarkdownRenderer` maps `<h1>` to `<h2>`; a body with no visible text counts as no block; no cross-locale fallback (a locale without a row gives null).
- Twig (`ContentBlockExtension`): `content_block(key, fallback = null)` (safe HTML, else the escaped fallback in a `<p>`, else `''`; may query once), `content_block_peek(key)` (pool only: footer, error pages), `content_text(key)`. Capture it, `{% set x %}{{ content_block(...) }}{% endset %}`: a plain `{% set x = ... %}` loses `is_safe` and escapes the HTML. Never `|raw`.
- The footer note (`templates/shared/_footer_note.html.twig`) peeks only, so error pages stay query-free (`ErrorPagesQueryFreeTest`); with a cold pool (fresh `var/share`, `cache:pool:clear`) it is missing until a listing or landing hit warms the snapshot, and pages cached meanwhile keep lacking it (a deploy keeps `var/share/<env>/pools`). Tests: `tests/Support/Cms/ResetsContentBlocks` (call `resetContentBlocks()` once the kernel is booted and again in `tearDown()` before `parent::tearDown()`).
