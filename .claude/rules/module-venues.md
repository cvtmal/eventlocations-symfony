### Venues

Venue aggregate (translations, terms, rooms, photos, documents, the Google place ID), detail page, import. Our own rating and reviews are retired since #53 (see **Built in #53**).

**Built in #4 (`venue-schema`).** Migration `Version20261030114442`; mapping `orm.mappings.Venues`.

- **Tables:** `venues` is the aggregate root. `venue_translations`, `venue_slug_history`, `venue_terms`, `venue_rating_highlights` and `venue_reviews` (both retired in #53: no reader or writer, dropped by the gated commit `google-rating-drop`), `rooms` → `room_translations`, `venue_documents` → `venue_document_translations` and `venue_photos` → `venue_photo_translations` hang off it with `ON DELETE CASCADE`. `towns`, `cantons` and `taxonomy_terms` are referenced with `RESTRICT`.
- **`venues`:** `number` is an identity column (`GENERATED ALWAYS`, unique). It is the stable public number and the Merkliste id (S7), not the PK. `tier_rank` (1–5) is generated from `tier` with `Tier::rank()`'s ranks; order listings by it. When there is a town, `canton_code` is the town's canton: the entity sets it from the town, the DB does not check it. There is no `venues.slug`: the slug is per locale in `venue_translations` (unique per locale), together with the summary (≤ 200), description, meta description and parking text. Read them with `TranslationJoin::localized('venue_translations', 'venue_id', 'v.id', 't')`; the same works for rooms, documents and photos. The name stays on `venues`. `room_count`, `largest_room_m2` and `max_room_height_m` are written by the write side from the rooms (DemoStory now, #9 later). `rating_score`/`rating_count` are retired in #53 (still mapped for `SchemaInSyncTest`, no reader or writer; the gated drop removes them).
- **Terms:** `taxonomy_terms (term_group, code)` holds 90 rows seeded by the migration: 7 groups, `position` 1..n per group, and `primary_position` 1–11 for the building chips shown before "Alle Gebäudearten". `venue_terms (venue_id, term_group, term_code, is_main)` has a composite FK to it. `is_main` marks the main building and the main setting (at most one per venue and group, a partial unique index). Filter by code directly on `venue_terms`.
- **Vocabularies** in `App\Venues\ValueObject`: `TermGroup`, `Term` (VO: group + code), `Tier` (`rank()`), `VenueStatus`, `RatingHighlight` (`icon()` → #1's sprite ids; kept only for the retired mapping until #53's drop), `OwnCatering`, `FloorMaterial`, `Seating`, `ReviewerRole` (as `RatingHighlight`) and `Access` (derived, not stored; #6 sets the thresholds). Labels are in the `venues` catalogue: `<context>.<value>` (`tier.premium`, `rating_highlight.food`) and `term.<group>.<code>` (`term.building.castle`). Every enum on a CHECK column is pinned to its `IN` list by `VocabularyChecksTest`.
- **Entities / repositories:** `App\Venues\Entity\{Venue, VenueTranslation, VenueSlugHistory, TaxonomyTerm, VenueTerm, VenueRatingHighlight, VenueReview, Room, RoomTranslation, VenueDocument, VenueDocumentTranslation, VenuePhoto, VenuePhotoTranslation}`, unidirectional `ManyToOne` only. `Venue` has no setters: use `relocate()`, `changeTier()`, `publish()`/`unpublish()`, `changeCapacity()`, `changeContact()`, `changeDistances()`, `answerFaq()`, `summariseRooms()` and `changeGooglePlace()` (#53; `rate()` is gone, and `VenueRatingHighlight`, `VenueReview` stay mapped without a writer until the drop). Decimals are passed as strings (`'8.4'`) and read back as floats. `Room::offerSeating()/seatingMin()/seatingMax()` cover the four seating column pairs. `VenuePhoto` throws `Venues\Exception\RoomOfAnotherVenue` for a room of another venue. `VenueRepository`, and `TaxonomyTermRepository::byGroup()`.
- **Demo data:** one Foundry factory per entity in `src/Factory/` (no `TaxonomyTerm` factory: look the rows up). `App\Story\DemoStory` creates 60 fictional venues: every canton, the tiers 3/6/9/12/30, 1–5 rooms, 0–2 documents, no photos (since #53 no rating, highlights or reviews). It is seeded and idempotent (it skips when venues exist), needs the imported towns, and is loaded by `AppStory`, so `make seed` loads it. The faker locale is `de_CH`.
- **Tests:** `tests/Integration/Venues/VenueSchemaMigrationTest.php` has one rejection case per constraint, and a check that fails when a new constraint has no case. `tests/Integration/Migrations/SchemaInSyncTest.php` runs `schema:validate` inside `make test`.
- **Photos (#5, `Version20261030125302`):** `venue_photos` has `width`, `height` (the oriented original), `dominant_color` (`#rrggbb`) and `variants` JSONB `{"widths": [...], "formats": ["avif", "webp", "jpg"]}`, all NOT NULL with CHECKs. `VenuePhoto(Venue, ?Room, int $position, string $originalPath, GeneratedImage $image)`, `recordVariants()`, `width()`, `height()`, `dominantColor()`, `variants(): ImageVariants`. `VenuePhotoFactory` writes rows only (1600×1067, widths 360–1280), no files. DemoStory now gives every venue 3–8 photos (some rooms 1–2) and real PDFs (superseding "no photos" above); `app:media:regenerate` lives here (`Venues\Console\RegenerateMediaCommand` → `Venues\Command\RegenerateMedia`).

**Built in #9 (`venue-content-import`).** Migration `Version20261030140037`: `venues.content_key` (folder name, `uk_`, kebab CHECK) and `venues.content_hash` (SHA-256, only with a key), `rooms.content_key` (unique per venue), and the table `content_imports` (one row per run that is not a dry run: counts, `errors` JSONB `[{key, messages}]`).

- **Command:** `make sf c="app:venues:import [path] [--dry-run] [--only=key] [--prune] [--force]"` (`Venues\Console\ImportContentCommand`) reads `<CONTENT_ROOT>/venues/<key>/` (`CONTENT_ROOT` in `.env`, git-ignored `content/`; never commit content). Format, rules and options for the owner and #21: `docs/content-format.md`; schema `docs/content-format.schema.json` (draft-07, `opis/json-schema`), its enums pinned to the PHP enums and `taxonomy_terms` by `ContentSchemaVocabularyTest`.
- **Flow:** one `ImportVenueContent` dispatch (one transaction) per folder; a failing folder is reported and the run goes on (exit 1). `ContentReader` validates everything before any write; an unchanged `content_hash` skips the venue (a second run writes nothing); then `UnpublishMissingContent` (`--prune`) and `RecordContentImport`; the handlers purge the HTTP cache after their commit (`PurgeVenueCache` per changed or unpublished venue, `PurgeListingsCache` once per run that changed something) through `Venues\HttpCachePurger` (`purgeVenue(int)`, `purgeListings()`; no-op `NullHttpCachePurger` until #19 swaps the alias; implementations never throw). The console only dispatches.
- **Reuse (CMS #24/#25, one write path):** `Venues\VenueSlugs::assign()` (slug + history), `TownResolver` (throws `UnresolvedTown`), `RoomSummary::apply()` (room facts from the venue's rooms), `PhotoPipeline` (`openStaging` → `stage` → `add` → flush → `publish`, `discardStaging`; `ValueObject\StagedPhoto`), `DocumentPipeline` (`store` → `add` → flush → `publish`), `PublishedMedia` (`revert()` on failure), and after the commit `RemoveVenueFiles`, `PurgeVenueCache`, `PurgeListingsCache` (all with `DispatchAfterCurrentBusStamp`). Compose them; never duplicate their rules.
- **Rules:** a venue with a `content_key` is written only by the import. The key is immutable; the number stays. Rooms keep their row by `content_key`, photos by `(room key, original_path)` and documents by `path`, where originals are content-addressed (`MEDIA_ROOT/content/<key>/<sha256>.<ext>`): a renamed or reordered file keeps its id and variants, changed bytes get a new photo. Every other child set (terms, all translations) is replaced. Since #53 the import neither reads nor touches highlights or reviews, and the content format refuses `rating` and `reviews`. Positions move in two flushes (offset +10000) because the position uniques are not deferrable. Slugs come from the name (`SlugAllocator`: name, `-<town-slug>`, `-2`…); the old slug goes to `venue_slug_history`, a rename back deletes that row, and history slugs stay reserved. Files of removed rows are deleted by `RemoveVenueFiles` (dispatched with `DispatchAfterCurrentBusStamp`, so only after the commit).
- **Tests:** build fictional folders at runtime with `tests/Support/Content/ContentFolder.php`; the integration tests use the `RunsContentImport` trait (rolled-back transaction, media dirs cleaned). `Venues\HttpCachePurger` is `Tests\Support\Http\RecordingHttpCachePurger` in the test env (`venues`: purged numbers in order, `listings`: count).
