### Crm

Back-office CRM (`/admin/crm`; model: S13 in `docs/rpi-cycles.md`): Locations (the code's `Company`) with their contact card, deals, tasks, activities and the inquiry inbox. Read it for CRM work and when another module must reach the CRM. A contact is a row on its Location's card, never a record of its own; couples are no contacts. Screens say **Location** (company) and **Eintrag** (venue); code, tables, routes and the ICU placeholder `companies` keep `Company`. Portal's staff screens say Eintrag too (`module-portal.md`); `/konto` keys, role names and the `cms` keys shared with `/konto` (`module-cms.md`) keep "Location".

## Boundaries
- **Imports:** never Cms, so `Crm\CrmApi` and `admin-ui/src/crm/failure.js` repeat `Cms\VenueMediaApi` and `cms/text.js`; from Portal only its events.
- **Writes:** a venue changes only through a Venues command. `MarkDealPaidHandler` dispatches `RecordSubscriptionPayment` unstamped on purpose (nested: one transaction, purges and the funnel step after the root dispatch), while `CreateCompanyForVenue` only reads the venue. Kit and JSON endpoint rules: `module-admin.md`.

## Data model
- `crm_companies`: `stage` `prospect|customer|former_customer`, `origin` `manual|venue`; `venue_id` = the Eintrag (`uk_crm_companies_venue_id`, `ON DELETE SET NULL`: deleting either side frees the other).
- `crm_contacts`: `company_id` NOT NULL CASCADE; no `kind`, no owner; `email` lower-case (`ContactEmail::normalise()`), NULL when empty, unique per Location (`uk_crm_contacts_company_email`).
- `crm_activity_types` are rows (new type = insert; `position` unique, next free 8); activities link via `crm_activity_{companies,deals}`; `Activity::$payload` holds an empty payload as `\stdClass` (`[]` fails `chk_crm_activities_payload`).
- `crm_deal_stages` rows `new contacted offer negotiation won lost` (one `is_won`, one `is_lost`); new stage = migration + `deal.stage.<code>` + `TimelineProps::DEAL_STAGES`. `crm_deals`: company, owner RESTRICT; venue SET NULL; `renewed_from_id` UNIQUE. A Location with a deal cannot be deleted (`CompanyHasDeals`); `company_id` has no write path.
- `crm_tasks`: `due_on` required; `chk_crm_tasks_one_object` = at most one of company, deal; partial `uk_crm_tasks_renewal` survives completion, so a done renewal task is not rewritten.
- `crm_inquiry_links`: key `inquiry_id` (CASCADE: goes with the inquiry under `app:inquiries:purge`), `status` `new|seen|done`, `activity_id` SET NULL (NULL without a Location); no row = never ingested. Inquiry data and mail outcomes are read live from `inquiries`, never copied.
- `crm_email_templates`: unique case-sensitive `name`; no `crm_emails` (a sent mail is an `email_sent` activity).
- Location delete cascades contacts, tasks, links; `DeleteCompanyHandler` then drops activities left on no timeline (`ActivityRepository::deleteUnlinked()`). Removing a contact deletes its row only; the Location's entries, tasks and deals stay. No per-contact export, erase or purge (S13). The Datenschutz section `legal.privacy.crm` (`shared` domain) must stay true to what the CRM stores: a Location's people and notes.

## Routes and roles
UUID parameters only; `ROLE_EDITOR` by class, `ROLE_ADMIN` for CSV exports, company and deal delete, template screens.
- `admin_crm_companies*` `/admin/crm/locations` (`?venues=` tabs); POSTs `_link_venue` `/{id}/eintraege`, `_unlink_venue` `/{id}/eintraege/{venueId}/entfernen`, `_contacts_{create,edit,remove}` `/{id}/kontakte[/{contactId}[/entfernen]]`; `admin_crm_company_from_venue` `/admin/crm/eintraege/{venueId}/location`; `admin_crm_contacts_export` `/admin/crm/kontakte/export`.
- `admin_crm_deals*` `/admin/crm/deals` (board; `?ansicht=liste` list), `admin_crm_tasks*` `/admin/crm/aufgaben`, `admin_crm_inquiries*` `/admin/crm/anfragen`, `admin_crm_email_templates*` `/admin/crm/vorlagen`; JSON `admin_api_crm_*` under `/admin/api/crm` (mails: POST `/emails`, GET `/email-draft`).
- `Legacy{Company,Contact}PathController` (`admin_crm_firmen_redirect*`, `admin_crm_kontakte_redirect*`) 301 old `/admin/crm/firmen...`, `/kontakte[/{uuid}]` GETs (query kept; a route parameter wins over a same-named query key); old POST paths are not redirected.

## JSON and inline edit
- **JSON:** `CrmApi` parses payloads into `Crm\Form` DTOs and `CrmApi::failure()` answers 422 `{"errors": {"field": [...]}}`, 409/404/403 on `""`. `adminFetch` keeps no body for 403/404/409, so islands bring own labels (`failure.js`: `failureOf()`, `formFailure()`). A 2xx needs a JSON body or 204: a non-JSON 2xx reads as a lost session (`module-admin.md`).
- **Inline edit:** PATCH `{field, value, expected}`; `expected` = loaded value, the version (S12), compared under the row lock. `CompanyProperty`/`DealProperty` allow-list fields; `PropertyConstraints` holds each field's rules for inline edit and create form; `PropertyValue::canonical()` is the one canonical form. `PropertyRow`: amounts are Rappen, so the row edits `draft`, shows `display`, `value` stays the version; a date refuses `validity.badInput` (a half-typed date never erases a stored one).
- **No-op rule:** `AuditLogMiddleware` audits every successful `AuditableCommand`, no skip, so a handler returning early still leaves a row: read state, dispatch nothing when unchanged (the property, toggle, link and contact-card controllers do); the handler re-checks under the lock. Two simultaneous identical saves may leave one extra row. A summary never holds a value or text and is never empty (`changes` must be a JSON object).

## Timeline
- **Read:** `TimelineQuery::page()` (20 per page), `TimelineProps::of()` (the island's props with the first page; one statement more for the mail templates, only on a record with an address), `TimelineApi`. System rows (publish, unpublish, tier change of the Location's Eintrag) come from `AuditLogQuery::forSubjects()` via `SYSTEM_COMMANDS`, on a Location with no type filter. Both sources have UUID ids and whole-second times, so one `(time, id)` pair orders merge and keyset. `ACTIVITY_JOINS` LEFT JOINs the inquiry, so `TimelineEntry::$inquiryId` and `$inquiryCouple` go null with the purge. Bodies are plain text (escaped, never `v-html`, line breaks kept); an entry on a deal also links its Location.
- **Write:** `OwnActivity::lock()` mirrors `TimelineEntry::canBeEditedBy()`: own, composable, not anonymised; a foreign entry is refused for `admin` too.
- **`RecordKind`** (`Company`, `Deal`): a new case makes PHPStan flag every `match` over it (`recordTable()`, `linkTable()`, `linkColumn()`, `taskColumn()`, `LogActivityHandler`, `CreateTaskHandler`); also needed: link table, `crm_tasks` column + replaced `chk_crm_tasks_one_object`, `Task`'s constructor, timeline controller, island `kind` prop, `ActivityRepository::deleteUnlinked()`.
- **New entry type:** migration row, `TimelineActivityType` in `Crm\Extension`, a line `    <code>: { icon: ... }` in `admin-ui/src/timeline/types.js`, `activity.type.<code>` + `activity.tab.<code>` per visible type, `activity.compose.<code>.{placeholder,submit}` if composable (add to `CrmTranslationKeysTest`); `TimelineTypesPinTest` holds rows, registered types and `types.js` lines equal.

## Tasks and badges
- `TaskView` tabs `alle` (default; the heading count on the bare URL includes done tasks), `meine`, `heute`, `ueberfaellig`; Heute and Überfällig hold everyone's tasks. "Today" = `TaskDueDate::today($clock->now())`, Europe/Zurich. `ReturnPath::safe()` checks a toggle's `return_to`: only `/admin/...` passes, `/admin` is refused, so the dashboard sends `/admin/`. `crm_task_due(dueOn, done = false)` gives `{label, tone}`.
- `TaskAssignee::among()` is the one assignee chain (renewal, invoice): first active owner, else oldest active admin, else `NoTaskAssignee`.
- `TaskBadge` = viewer's open tasks, any due date; `InquiryBadge` = new inquiries; per-request memos. `OwnerOptionsQuery::all()` carries both as columns: pages that run it pay nothing, others one statement per badge.

## Deals
- **Create:** company first (`?company=<id>`; `VenueLookupQuery` has no company filter); the deal takes the Location's Eintrag; a posted `deal[venue]` is an extra field (422). `stage` is never a form field or `DealProperty`; a new deal starts at `new`.
- **Money:** `Chf` goes through strings, never a float (limit `MAX_RAPPEN`); `ChfTextType`, filter `chf` and `admin-ui/src/crm/money.js` share one output (`admin-ui/tests/fixtures/chf.json`). A `SUM` casts `::bigint`.
- **Stage moves** (`MoveDealStage`; every deal handler locks company, then deal, then venue): same target = no-op, another `expected` = `StaleProperty`, lost needs a `LostReason`, going back clears `closed_at` and the reason. The entry sits on deal and Location with a snapshot title and payload (the Location's timeline outlives a deleted deal). `ChangeDealLostReason` changes a lost deal's reason alone: no entry, stage and `closed_at` stay.
- **Derived stage** (S13): `CompanyStageSync` is the only writer; it writes SQL, so call it after a flush, and leaves `updated_at` alone. `ChangeCompanyPropertyHandler` refuses `stage` (`CompanyStageDerived`) while a won deal exists.
- **Tier:** a won deal's paid tier reaches the Location's own Eintrag only as a paid term («Zahlung erfassen», G9, see the end of this file); the offer is read live (`DealPaymentOfferQuery`), no flag stored. A tier is a `tiers` row (F12): commands carry its code (`CreateDeal::$tierCode`), `TierResolver` turns a code into the row (unknown: `InvalidPropertyValue`), tiers compare by code; a read model holds a `TierLabel` (name from the table, `promoted` colours the pill). `DealRecordQuery` folds the Tier field's options and `CompanyRecordQuery` the code => name map (`labels.tiers` of the timeline) into their own statement.
- **Renewals:** `RenewalWindow` (today through 60 days, Zurich; task due 30 days before the end, else today). `app:crm:renewal-tasks` reads only deals without a renewal task, so a night writes no no-op audit rows. An open renewal task follows its deal: leaving won or an emptied `contract_end` completes it, a new `contract_end` moves its due date.
- **Board:** 100 open + 20 newest closed per column. `deal.renew.name` takes the year as text (an integer in `+intl-icu` is grouped: "2'027").

## Inquiries and bridges into the CRM
Bridge listeners catch `\Throwable`, log class and place (never the message: it can quote an address) and never reach the guest, the approve or the publish; none is retried, only ingest has a nightly repair (`app:crm:backfill-inquiries`, silent at 0).
- **Ingest:** `IngestInquiryListener` on `InquirySubmitted` dispatches `IngestInquiry`; `IngestInquiryHandler` writes the `inquiry` entry (titled with the venue's name: no personal data is copied) and the link row; a venue without a Location (or gone) gets the link row only, no entry, no automatic Location. Not auditable (the link row is its record).
- **Inbox** (`?status=new|seen|done|all`, default `new`): neither GET writes. `ChangeInquiryStatus` is audited with the status code only, read first (no-op rule). A resend dispatches `Inquiries\Command\DeliverInquiry` for a venue mail `failed`/`pending`, unaudited: the cure for the hourly stuck-inquiry alert (`app:inquiries:report-stuck`, G7).
- **Confirmed manager:** `LinkLocationManagerListener` on `Portal\Event\LocationManagerConfirmed`/`LocationSubmitted` dispatches `CreateCompanyForVenue` when `VenueCompanyQuery::companyIdOf()` finds none, then `LinkLocationManager` (no backfill; cure: remove and add on the panel, which writes a second entry). The handler finds the contact by (Location, e-mail) or creates it with position `MANAGER_POSITION` ("Location-Manager"); an existing row keeps staff's values (blanks are filled), `/konto` changes never update it. It writes a `note` with no actor and no title on the Location only; no Location, nothing. Not auditable.
- **No invoice reminder since F12:** the sister site's rule that a first publish writes the task «Rechnung stellen» (Q20, POR-14: `CreateInvoiceTaskListener`, `CreateInvoiceTask`) is gone, because a new entry is Free and nobody invoices it (D2). `Venues\Event\NewVenuePublished` is still published, with no subscriber. `Crm\TaskAssignee::among(...$owners)` is the one assignee chain, renewal and Pro-request tasks included: the first active owner, else the oldest active admin. This task has no deal, so its chain starts at the company's owner; nobody active is `NoTaskAssignee`, and the company created just before stays.
- **Pro request (F12):** `CreateProTaskListener` on `Portal\Event\ProRequested` ensures the venue's company (`CreateCompanyForVenue`) and dispatches `CreateProRequestTask`, audited, subject `task`: `task.pro_request_title` (`ProRequestTitle`, at most 200 characters, the venue's name gives way), no `createdBy`, `TaskAssignee::among(company owner)`, due `TaskDueDate::daysAfter()`, 2 days. One open task of that title per company: the listener checks `VenueCompanyQuery::hasOpenTask()` first (P1), the handler again under the company lock and answers whether it wrote. A failure is logged by class and place and never reaches `/konto`.

## E-mail
- **Send:** `SendCrmEmailHandler` sends inside the command's transaction on purpose (staff keep the text); accepted cost: a commit failing after SMTP accepted leaves a mail with no entry and a 500. A transport, RFC or pipeline failure is an outcome: the entry commits as `failed`. Payload `{to, cc?, status}`; `to` stays the real address under the override. `EmailApiDeliveryFailureTest` sets the dead DSN before the client boots (the container reads it then): copy it for other dead-SMTP tests.
- **Override:** `INQUIRY_RECIPIENT_OVERRIDE` redirects every CRM mail and its CC (a CC left on would reach the real address); originals stay in `X-Crm-Original-Recipient`.
- **Merge:** `MergeFields::TOKENS` is the one token list, applied in one `strtr`: a value holding a token is not expanded again, a missing value is empty, an unknown token stays visible, never Twig; `{company.name}` is a silent alias (`LEGACY_COMPANY_TOKEN`) for stored templates. ICU trap: never write a `{token}` in a `+intl-icu` catalogue; pass tokens as a parameter.
- **Composer:** without an address the E-Mail tab only logs; Enter never sends (`type="button"`, `submit()` returns).

## Locations and the Eintrag
- **Eintrag:** `LinkVenue` refuses a second Eintrag on a Location (`CompanyHasVenue`) and another Location's venue (`VenueAlreadyLinked`); same pair = no-op; `UnlinkVenue` releases; moving = release, then assign, by hand. `CompanyRepository::lockVenue()` (the venue's advisory lock, shared with `CreateCompanyForVenue`) stops two writers giving a venue two Locations; `venueOf()` runs under the company lock.
- **Contact card:** `CreateContact`, `ChangeContact`, `RemoveContact` lock company, then contact; `ContactNotFound` for another Location's contact, `ContactEmailTaken` for a same-Location e-mail; audit subject `company` with `{contact, fields}`.
- **Bootstrap:** `app:crm:bootstrap` (run with `--no-debug`: the debug data holder grows per statement) and `BootstrapController` (`BATCH` 100) share `CompanyBootstrap::run()`: one company per venue that has none, one transaction each. A failure's reason is the constraint's name or the exception's class, never a driver message (it quotes contact values).

## Cron, CSV, crawler
- `bin/cron-daily` runs `app:crm:refresh-stages` and `app:crm:renewal-tasks` after `app:inquiries:purge`, each `--quiet` (`step` mails any output; a failure prints anyway), then `crm-backfill` without `--quiet` (a repair is worth the mail), before `inquiries-stuck`.
- **CSV:** all exports go through `Crm\CsvStream::response()` (`;`, UTF-8 BOM, CRLF, `escape: ''`; a cell led by `=`, `+`, `-`, `@`, tab or CR/LF gets a `'`).
- **Crawler** `app:crm:crawl-eventlokale [path]` writes every eventlokale wedding venue into `<root>/owner/eventlokale-hochzeit.csv`; owner-run and resumable, options `--refresh`, `--limit=N`, `--list-only`, `--from-cache` (no request), `--delay-ms`, `--jitter-ms`. Only robots-allowed `/api/guest/` paths. A failed detail or the 429 stop (`MAX_CONSECUTIVE_429`) exits FAILURE, but the CSV is still written. It never copies reviewer comments, contract data or counters. Pace, request-cap exemption and private data (`CONTENT_ROOT`, git-ignored): `docs/rpi-cycles.md`, Important.
