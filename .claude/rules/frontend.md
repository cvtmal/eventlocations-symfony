# Frontend conventions (conventions from #1 design-system, look from #35)

Target: the boards in `docs/reference/public/`. Component reference: `/_styleguide` (dev and test only) renders every component. Compare your page with both; the eventlokale screenshots in `docs/reference/` record behaviour only.

- **Tokens:** use only `var(--…)` from `assets/styles/abstracts/_tokens.scss` (colours `--c-*`, type `--fs-*`/`--lh-*`/`--fw-*`, numeric `--space-*` named by their px, `--radius-*`, `--shadow-float` for floating layers only). No hex values in partials. Breakpoints: `@use '../abstracts/breakpoints' as bp;` then `@include bp.up(md) { … }` (sm 568, md 768, lg 1024, xl 1440).
- **Your partial:** one per component at `assets/styles/<module>/_<name>.scss`, with one `@use '<module>/<name>';` line appended to the end of `assets/styles/app.scss` (hotspot: append only). `@use`, never `@import`; no `!important`. `app.css` stays ≤ 25 KB gzip (`AssetBudgetTest`).
- **Components** (`templates/components/`): include atoms with `{% include 'components/_x.html.twig' with {…} only %}`, embed shells with `{% embed 'components/_x.html.twig' with {…} only %}`. Pass already-translated strings. `search/_home_search.html.twig` and the other `home-*` markup of #36 are the home page's own, not components.
  - `_button`: `label`, `variant` (primary|secondary|ghost|round|round-lg|icon|close), `size` (md|lg), `href`, `type`, `icon`, `label_hidden`, `attributes`, `static` (a plain `<span>` with the button's look and no behaviour).
  - `_chip`: `label`, `href`, `remove_label`, `variant` (active|neutral). `_badge`: `label`. `_toast`: `message`, `link_href`, `link_label`.
  - `_text_input`: `id`, `name`, `label`, `type`, `value`, `placeholder`, `autocomplete`, `label_hidden` (default true), `help`, `error` (replaces `help`, sets `aria-invalid`), `icon`, `disabled`.
  - `_overlay` (shell): `id`, `tone` (region|guests|more), `title`, `close_label`; blocks `overlay_body`, `overlay_footer`.
  - `_dialog` (shell): `id`, `title`, `close_label`; blocks `dialog_body`, `dialog_footer`.
  - `_carousel` (shell): `id`, `label`, `previous_label`, `next_label`, `counter_format`, `scrollable` (default true; false for one slide: no tab stop); block `slides` (`<li class="carousel__slide">`).
  - Search partials (#7, include with `only`): `search/_card` (`card`, `index`, `action` merken|remove|none, `heading`; no rating since #53), `search/_card_facts` (`capacity_min`, `capacity_max`, `place`; the listing card is its one caller since #37), `search/_related_searches` (`links` list<{label, href}>, `title`).
- **Images:** venue photos only through `{{ venue_picture(picture, sizes=…, loading=…, priority=…, widths=…, class=…) }}` (Media); cards pass `widths=[360, 640, 960]`; one LCP image per page gets `priority=true`, and the other eager photo (`loading='eager'`, a listing's second card, LP-3) prints `fetchpriority="low"` so it never sits in the LCP image's way; a card's slides after the first pass `decorative=true` (`alt=""`, their link is aria-hidden); never a raw `<img>` for a venue photo and never a `style` background (the placeholder is an SVG `fill`).
- **Icons:** `{{ icon('name', {label: '…', class: 'icon--sm'}) }}`; without `label` the icon is decorative. A new icon is a `<symbol id viewBox="0 0 24 24">` added to `assets/icons/sprite.svg` (sorted by id, no `stroke`/`fill` attributes) plus a line in `assets/icons/LICENSES.md`. `IconSpriteTest` fails on an unknown name.
- **JS:** one self-contained module per behaviour in `assets/js/` (no `import`/`export`, no globals, no `console`), loaded with `<script type="module" src="{{ asset('js/x.js') }}"></script>` in `{% block scripts %}`. No `importmap()`, no inline `<script>`, no `style` attribute or `<style>` (CSP, #16). The one exception is JSON-LD through Seo's `*_jsonld()` functions, which the browser never executes. Public pages are cached, so a public page that needs inline code uses a hash, never a nonce; `csp_nonce()` is for `no-store` pages (`/admin`). User-visible strings reach JS through `data-*` attributes. ≤ 15 KB gzip JS per page. `near-me.js` (#52) and `google-rating.js` (#53) are the two exceptions to "no globals" and the two modules that inject a third-party script (the Maps JavaScript API, S1). `near-me.js` sets Google's documented `window.gm_authFailure` and the loader's `callback`, `window.nearMeMapReady` (hotfix `near-me-callback`), on `nearby` only, under that route's own CSP. `google-rating.js` (detail page, ≤ 2 KB gzip) sets `gm_authFailure` and the bootstrap's `callback` global `googleRatingReady` (deleted when called): with `loading=async`, `google.maps.importLibrary` does not exist yet at the script's own `load` event, so build on the callback, not on `load`. It starts only after the page's load event and the box's first intersection, builds `gmp-place-details-compact` from documented elements and attributes only, and falls back to the server's link on every failure (script error, `gm_authFailure`, a rejected `importLibrary`, `gmp-error`); `gmp-load` hides the link. Its CSP (`google_places`) is set by the server only when the box renders.
- **Overlays:** `popover` + `popovertarget` (works without JS) plus `js/overlay.js` (focus in, Tab wraps). **Dialogs:** `<dialog>` opened by `commandfor`/`command="show-modal"` plus `js/dialog.js` (fallback, backdrop close). **Carousels:** scroll-snap track plus `js/carousel.js`; the counter reads the first slide in view over the slide count, and the last page reads the total (12 slides 3-up: 1, 4, 7, 12).
- **Live count in a filter overlay (`js/live-count.js`, #10; `listing.html.twig` already loads it):** give the overlay's GET form `data-live-count data-live-count-url="{{ path('_search_count') }}?"` (the URL ends in `?` or `&`; a form built with #17's `listing_form()` takes its `count`, which carries the landing path's facets) and put `_hidden_state` plus the named controls inside it. The footer button is `_button` with `type: 'submit'`, `variant: 'primary'`, `size: 'lg'` and `attributes` `form` (the form's id), `data-live-count-label`, `data-count-zero`, `data-count-one`, `data-count-other` (`filter.show_results` with count 0, 1 and 2 + `formatted: '%n'`). It recounts on `input`, `change` and when the overlay opens, and the query is exactly what the form submits, empty values dropped, after the URL's own facets. After setting a value from JS, dispatch `new Event('change', {bubbles: true})` on the control. There is no global API. `[hidden]` has no global rule, so a class that sets `display` needs its own `&[hidden] { display: none; }`.
- **Overlay form (`js/overlay-form.js`, #12; `listing.html.twig` already loads it):** give a filter overlay's form `data-overlay-form` and its reset link `data-overlay-clear`. The link then empties the form (checkboxes and radios unchecked, text and selects emptied, never hidden inputs), stays open and recounts; closing the overlay runs `form.reset()`, so what was not applied is discarded. Without JS the link navigates.
- **Submit buttons beside an overlay's input** (bubbles, presets) go in a sibling form with its own `_hidden_state`, never in the input's form: the first submit button in tree order is the form's default button, so Enter in the input would submit it (#11).
- **Filter data:** a filter control shows when it has data or is active (`filter_has_data(key)`, `filter_terms(group, criteria)`). Never offer a search that always returns 0, and never hide an active value.
- **Contrast:** text on `--c-accent-strong` is `--c-on-accent`. No pink ground behind text except the primary button and the count badge. Only `--c-ink` on `--c-accent-soft`; the one exception is `.btn--secondary`'s hover and active text, `--c-accent-strong-hover` and `--c-accent-strong-active`. No `--c-ink-muted` or `--c-accent-strong` text on `--c-overlay-circle`, with two answers: a placeholder is `--c-ink-muted` there only from 24 px, as large text (4.33:1), and the clear link of Region and Guests is `--c-accent-strong-hover` (5.39:1, where `--c-accent-strong` would read 4.25:1). Inactive states use weight or underline, never opacity. A new colour pair gets a row in `tests/Unit/Shared/ContrastTokensTest.php`.
- **Slots** (fill them, do not restructure `templates/base.html.twig` or `templates/layout/*`):
  - `base.html.twig` blocks: `title`, `meta`, `canonical`, `hreflang`, `stylesheets`, `jsonld`, `body_class`, `hero`, `main`, `scripts`;
  - header link targets in `layout/_header.html.twig`: Locations is `path('listing')`, Regionen `/#regionen` (`path('home') ~ '#regionen'`, #36), the heart `path('merkliste')` (#13);
  - listing filter bar: `templates/search/filter/_{region,guests,more}.html.twig` (#10, #11, #12; variables `criteria` + `part` `chips|trigger`, render `<li class="filter-bar__item">`s), never `search/_filter_bar.html.twig` itself; `search/filter/_hidden_state.html.twig` (`criteria`, `except`) for their GET forms;
  - `favorites/_merken_button.html.twig` (`number`, `name`, `label`, `variant` card|detail) and `favorites/_remove_button.html.twig` (`number`, `name`), both owned by #13: POST forms to `merkliste_toggle` with the constant `_token`, taken over by `js/merkliste.js`; `_remove_button` also posts `intent=remove`, so it only ever removes;
  - `layout/_main_menu.html.twig`: append one `<li>` per menu item;
  - header, phone menu and footer carry the near-me link "In der Nähe" (`path('nearby')`, #52);
  - footer includes `seo/_footer_cantons.html.twig` (#17) and `site/legal/_footer_links.html.twig` (#18), both `ignore_missing`;
  - the toast live region `[data-toast-region]` in `base.html.twig` (#13);
  - the styleguide map slot `styleguide/_canton_map.html.twig` (#3).
- **Checks for every UI cycle:** `make lighthouse URL=/path` (reports in `var/lighthouse/`), `make validate-html URL=/path`, the screenshot comparison at 390 and 1440 px, and a keyboard-only walkthrough.
- **Back office (#23, `/admin` only):** the rules above apply, with `--a-*` tokens from `assets/styles/admin/_tokens.scss`, partials in `assets/styles/admin/` appended to `assets/styles/admin.scss`, and icons through `{{ admin_icon() }}`. Build screens from the kit in `templates/admin/components/` (atoms by `include … with_context = false`, shells by `embed … only`, strings translated; every variant on `/admin/_styleguide`), never from `templates/components/`. Forms use `{% form_theme form 'admin/form/theme.html.twig' %}` per template; never set `twig.form_themes`, which would reach the public forms. Vue components are `admin-ui/src/components/Ui<Name>.vue`, the twin of the Twig partial with the same classes and markup, imported only by islands; JSON goes through `adminFetch` (`admin-ui/src/api.js`). Back-office scripts live in `assets/js/admin/` and are loaded by `templates/admin/components/_scripts.html.twig`, not by `{% block scripts %}`. The one exception to "no `import`": `assets/js/admin/palette-trigger.js` calls `import()` on the deferred island entry, whose URL is a variable, so AssetMapper leaves it alone.
